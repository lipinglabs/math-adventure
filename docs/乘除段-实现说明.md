# 乘除段（L28–L48）实现说明

> 依据：《乘除段 21 关按关策划案（定稿）》。
> 一句话：**21 关共用一套题型原语，关卡文件只做接线；所有数字都在 `cd-data.js` 里，不在实现者直觉里。**

## 1. 文件分工

| 文件 | 职责 | 谁可以改 |
|---|---|---|
| `cd-art.js` | 乘除段素材库，**全部内联 SVG**（零图片请求） | 改画法可以，改接口要同步 4 个题型文件 |
| `cd-kit.js` | 题型引擎内核：`valid()`、字段层、容器排布、计数轨、四幕调度、记录与星级 | 改行为要重跑全段回归 |
| `cd-type-give.js` | 「发」家族：T4a 发一轮 / T4b 发到发不动 / T4d 补一个 | 按题型改 |
| `cd-type-build.js` | 「建」家族：T1a 长一份 / T1c 长一行 / T3a 装一盒 / T2 点着数 | 按题型改 |
| `cd-type-judge.js` | 判断家族 T5/T6/T7a/T7b/T7c/T8 + 串联 serial | 按题型改 |
| `cd-data.js` | **21 关 168 槽的全部参数与题干 key**，含构建期断言 | 唯一数据源，先改这里 |
| `level-lvNN.js` | 接线外壳（约 45 行），把 `CD_DATA[NN]` 交给 `CDKit.mount` | 一般不用动 |
| `levels_data.js` | 只保留外壳要用的名字、背景图、语音预加载清单 | 名字与 audio 清单由脚本生成 |
| `tools/cd-lines.js` | 全部文案（301 条 + 35 个数字片段） | 文案唯一源 |
| `tools/cd-validate.js` | 168 槽断言（valid / 末槽 / 步数 / 真数量选项） | 规则变了才改 |
| `tools/cd-probe.mjs` | 真机验收探针（CDP）：自动玩一关，收集异常/404/结算/截图 | 验收用 |

## 2. 数据形状

```js
CD_DATA[28] = {
  id: 28, name: 'Two Plates', tier: 'M1',
  intro: { props: ['plate','plate','bun','bo'], lines: ['lv28/s0a','lv28/s0b'] },
  demo:  { type: 'T4a', a: 2, b: 2, total: 4, item: 'bun', container: 'plate', lines: [...] },
  outro: { style: 'last' | 'quad' | 'ring', marks|cells, lines: [...], hold },
  slots: [ { type:'T4a', a:2, b:2, total:4, q:'lv28/s1' }, ... ]   // 6 或 8 个
}
```

- `only8: true` 的三关（L46/L47/L48）永远 8 槽；
- 其余关**首玩 6 槽、重玩 8 槽**，由 `Progress.starOf(id) !== 'none'` 判定（`cd-kit.js` 的 `activeSlots()`）；
- 记录三字段分开：`built`（建模型）/ `built2`（点着数、两种数法）/ `judged`（判断型），互不复用。

## 3. 硬约束落在哪

| 约束 | 落点 |
|---|---|
| `valid(a,b)`：2≤a≤5、2≤b≤5、a×b≤20 | `cd-kit.js` 的 `valid()`，`cd-data.js` 逐槽调用 |
| 建模槽不判对错、无数字键、无确认键 | 建模型只挂一个 `.cd-main` 动作按钮 |
| 判断型选项必须是「真画出来的数量」 | `optionCard()` 只画实物，不写数字字形 |
| 末槽必须是建模型或动作型 | `cd-data.js` 的 `validate()` |
| 5 容器 = 3+2 + 底部 5 点计数轨 | `layoutBoxes()` + `countRail()` |
| 320 宽降级（容器 ≤74、间距不压） | `layoutBoxes()` / `box-probe` 的 320 用例 |

## 4. 四幕

1. **幕 1 引入**：道具一字排开（多道具自动缩、可换行），两句语音；
2. **幕 2 示范**：`spec.demo` 直接交给对应题型跑一遍，`is-demo` 虚线框 + 不记录判定；
3. **幕 3 逐槽**：每槽先`resetStage()`，再读题干，再进题型；
4. **幕 4 收束**：`outro.style` 三选一（`last` 一排实物 / `quad` 四格对比 / `ring` 首尾环）。

单个槽抛错**不会拖死整关**：`mount()` 里逐槽 catch，记一条 `built.note='exception'`，继续下一槽并照常结算。

## 5. 语音

- 文案：`docs` 外的 `tools/cd-lines.js` → `voice/lines/lvNN.json`；
- 生成：`python tools/gen_tts.py voice/lines/lvNN.json --out voice/lvNN`；
- 打包：`node tools/pack-voice.js`（把每关 mp3 拼成 `voice/packs/lvNN.bin`，进关只发 1 个请求）；
- 预加载清单：`node tools/cd-audio-list.js` 把 `levels_data.js` 的 `assets.audio` 换成本关真实 key（含 T2/T5 会念到的 `common/num_NN`）。
- **顺序**：改文案 → 重生成 mp3 → `cd-audio-list` → `pack-voice`。

## 6. 怎么验

```bash
# 1) 数据断言（168 槽）
node tools/cd-validate.js

# 2) 起本地静态服务（探针默认连 8123）
python -m http.server 8123 --bind 127.0.0.1 &

# 3) 单关真机验收（自动玩、截图、收集异常）
node tools/cd-probe.mjs 28 45            # 首玩 6 槽
node tools/cd-probe.mjs 28 30 --twice    # 连玩两遍：6 槽 + 8 槽
```

探针判定标准：`star` = gold、`exceptions: 0`、`网络: 0`、`active` 等于该关槽数。
截图落在 `.shots/cd/lvNN/`。

## 7. 已知取舍

- **落位以内腔为准，不是以外框为准**：容器「能装东西的那块区域」写在 `cd-art.js`
  的 `INNER`（viewBox 坐标），`Field.box()` 用 `svg.getScreenCTM()` 把它映射成屏幕矩形，
  `inBox()` / `fitSize()` 都在这个矩形里排布。按外框排会出两个错：面包停在盒盖上、
  卡在盘沿上（画出来的盒身总比外框小一圈，阴影和盘沿还要占位）。改容器画法时
  `INNER` 必须跟着改。
- **`transform` 由 Field 独占**：任何「出场弹一下」必须走 `U.popIn()`，不许自己写
  `el.animate([...], { fill: 'both' })` 并带上 `transform` 关键帧。`fill:'both'` 的动画
  结束后仍会压住内联 `transform`，物体算好了新坐标却还钉在原地（盒子看起来永远是空的）。
  `popIn` 在 `finished` 时 `cancel()`，探针的 `动画残留(stuck)` 必须为 0。
- 背景照片沿用 `levels_data.js` 里每关原有的 `assets/bg/bg_NN.webp`，不改图；正文压在
  `.cd-board` 的柔白桌面（径向渐变 + 3px 背景虚化）上，保证实物可辨。
- `levels_data.js` 里 L28–L48 的旧 `questions` 数组已删除：那套题目属于重做前的内容，
  留着会被间隔复现误取；新内容只在 `cd-data.js`。
